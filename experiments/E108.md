## E108 PRE-REGISTRATION - what does an agentic harness actually COST per conversation, and does it fit llama.cpp's grammar builder? (2026-09-05)

**Registered before the instrument is built.** `results/raw/e108` does not exist
and no harness request has been captured.

### Why this experiment exists

| | |
|---|---|
| **which success question** | local agentic coding - the one branch this repo has PROVED and still cannot fully explain |
| **uncertainty reduced** | whether any harness other than Aider can drive local models here, and by how much they differ |
| **decision that changes** | which client `tools/local-code` wraps. Today it is Aider by elimination, not by comparison |

**F103-F105 established that the binding constraint on local agentic coding is
the HARNESS, not the model.** Claude Code cannot drive our local models at all -
a ~44,912-token floor and ~73 KB of tool-schema JSON, failing in 95 ms - while
Aider drives the SAME weights first-try on 761 tokens. That is a ~60x difference
in overhead attributable entirely to the client.

**Nobody publishes these numbers.** A survey of the field (2026-09-05) returned
overhead figures for one harness out of eleven, and that figure turned out to be
THIS REPO'S OWN Aider measurement attributed to a different tool. The gap is
real, and we already own the only instrument that has ever produced such a
number.

### The instrument, and why it needs NO GPU

A **recording proxy**: an HTTP server presenting both the OpenAI-compatible
`/v1/chat/completions` and the Anthropic `/v1/messages` endpoints, which writes
each request body verbatim to disk and returns a minimal valid response. Each
harness is pointed at it and asked to start one task.

**This measures the harness, not the model, so it consumes no GPU** and cannot
contend with E106. That is the design's main virtue: it is the one useful thing
this box can do while it is busy.

### The metrics, primary first, and why the primary one is tokenizer-free

| metric | why |
|---|---|
| **PRIMARY: tool-schema bytes** | F104 located the blocker in llama.cpp's GRAMMAR BUILDER, at roughly 70 KB. That is a byte threshold, so it is exact and needs no tokenizer |
| system-prompt bytes | the other half of the floor |
| tool count, and tool-calling vs prompted-diff | F114: the edit format decides which jobs work |
| SECONDARY: prompt tokens | needs a tokenizer. Deferred, and when taken it comes from the TOKENIZER, never chars/4 - technical text runs ~40% over |

### THE POSITIVE CONTROL, RUN BEFORE ANY NEW ARM (F100)

Two harnesses have known values from this repo's own measurements. **The proxy
must reproduce both before any unmeasured harness is run.**

| control | must show |
|---|---|
| **Claude Code** | tool-schema bytes in the **60,000-90,000** range (F104 measured ~73 KB) |
| **Aider** | a request carrying **no tool schema at all** - F105/F114 establish it uses prompted edit formats, not tool-calling |

**If either control fails, the instrument is wrong and no other arm runs.** An
instrument that cannot reproduce a value we already hold cannot be trusted with
one we do not.

### The arms

**Stage 1 - installed today, no new software:** Claude Code (control), Aider
(control), **Hermes** (installed, never tested - carried in memory as "test
queued" since before 2026-08-30).

**Stage 2 - conditional on the controls passing:** install and measure **Goose**
and **OpenCode**, the two candidates a field survey rated plausible for local
use. Installing software to measure it is a cost, and it is not paid until the
instrument has proved itself.

### Predictions, each naming the FIELD it is scored against

| # | prediction | scored against |
|---|---|---|
| 0a | **CONTROL: Claude Code reproduces** | its captured `tools` array serialised length, **60,000-90,000 bytes** |
| 0b | **CONTROL: Aider carries no tool schema** | its captured request has `tools` absent or empty |
| 1 | **DISCRIMINATING: Hermes does not fit either** | Hermes tool-schema bytes **> 70,000**, i.e. above F104's grammar-builder threshold |
| 2 | tool-schema bytes dominate system-prompt bytes for any tool-calling harness | for every arm with a non-empty `tools`, schema bytes **>** system-prompt bytes |
| 3 | at least one harness besides Aider is viable here | some arm has tool-schema bytes **< 10,000** |
| 4 | the published field figures are wrong | no third-party-published overhead figure for any arm lands within **20%** of measured |
| 5 | the instrument holds | every arm produces **>= 1** captured, JSON-parseable request |

**P1 is registered in the direction that costs us nothing to be wrong about.**
If Hermes turns out to fit, that is a better outcome than the prediction, and it
is a harness the owner already installed.

### Registered decision rule

| observed | action |
|---|---|
| either control fails | **STOP.** Fix the proxy; report nothing about any other harness |
| P1 holds and P3 fails | Aider stays by elimination, and it is now elimination on MEASURED grounds rather than on having tried one thing |
| **P3 holds** | a real alternative exists. It gets a capability run against `tools/aider-tasks.json` before any recommendation - overhead is necessary, not sufficient (F87: a model can have good capability and be a poor system component; the same is true of a client) |
| P2 fails | the mental model is wrong: the floor is the system prompt, not the schema, and F104's diagnosis needs revisiting |

### What this cannot establish

- **Overhead is not capability.** A harness that fits may still drive the model
  badly. This experiment ranks admissibility, not quality, and the decision rule
  refuses to recommend on it alone.
- **One task shape**, one repo, one model's tokenizer for the secondary metric.
- **Versions drift.** Every figure is stamped with the harness version; Aider is
  `0.86.2` today.
- **Nothing about IDE-embedded clients** (Cline, Roo, Continue) which cannot be
  driven headlessly here.


## E108 STAGE 1 RESULT - both controls reproduced, and Hermes FITS. PREDICTION 1 FALSIFIED. (2026-09-05)

Three harnesses, measured on the wire by `tools/harness_probe.py`, no GPU, no
model. Aider `0.86.2`; Claude Code and Hermes at today's installed versions.

| harness | system prompt | **tool schema** | tools | total request | mechanism |
|---|---|---|---|---|---|
| **Aider** | 5,321 B | **0 B** | 0 | 11,121 B | 12 few-shot messages, prompted diffs |
| **Hermes** | 19,791 B | **48,812 B** | 28 | 67,933 B | tool-calling |
| **Claude Code** | 7,038 B | **80,594 B** | 54 | 165,566 B | tool-calling |

### The controls passed, which is what licenses the rest

| control | registered | measured | |
|---|---|---|---|
| 0a Claude Code schema | 60,000-90,000 B | **80,594 B** | **HELD** |
| 0b Aider carries no schema | absent/empty | **0 B, no `tools` key** | **HELD** |

F104 measured Claude Code's schema at ~73 KB in a different session by a
different method on an older version; this lands at 80,594 B, inside the
registered window. **An instrument that reproduces two values already held can
be trusted with one it does not.**

### Scoring

| # | prediction | outcome |
|---|---|---|
| 0a | Claude Code 60-90 KB | **HELD** - 80,594 B |
| 0b | Aider no tool schema | **HELD** - 0 B |
| 1 | **DISCRIMINATING: Hermes does not fit either (> 70,000 B)** | **FALSIFIED** - 48,812 B, comfortably under |
| 2 | schema bytes dominate system-prompt bytes for tool-calling harnesses | **HELD** - Hermes 48,812 vs 19,791; Claude Code 80,594 vs 7,038 |
| 3 | some harness besides Aider under 10,000 B | **FALSIFIED** - Hermes is the only other arm and is 48,812 B |
| 4 | no published figure lands within 20% of measured | **FALSIFIED, and in the arm's favour** - `hermes prompt-size` self-reports 48,598 B / 28 tools against a measured 48,812 B / 28 tools, a **0.4%** difference |
| 5 | every arm yields a parseable capture | **HELD** - 1, 4 and 2 captures respectively |

### THE ANSWER

> **There is a second admissible harness on this box, and it was already
> installed.** Hermes' 48,812 B of tool schema sits under F104's ~70 KB
> grammar-builder threshold where Claude Code's 80,594 B does not. The
> registered prediction that it would also fail is falsified.
>
> **P2 holds decisively and locates the problem precisely.** The three system
> prompts span 5-20 KB; the schemas span 0-81 KB. **The instructions are not the
> cost. The tool schema is**, and it is the whole difference between a harness
> that runs here and one that fails in 95 ms.

### Overhead is a CONFIGURATION, not a property of the harness

Hermes' 28 tools include a complete browser suite - `browser_click`,
`browser_scroll`, `browser_vision`, `browser_snapshot`, `browser_navigate` - sent
on a request to edit one Python file. Claude Code's 54 include `CronCreate` and
`CronDelete`. **Neither is sending a schema sized to the task.**

Hermes exposes `hermes tools disable`. That reframes the question from *which
harness is cheapest* to *how cheap can a harness be made*, and it is directly
testable rather than speculative. Registered as E108 stage 1b below.

### P4's falsification is worth more than its holding would have been

The prediction assumed published overhead figures would be wrong. Hermes'
self-report is accurate to 0.4% with an exact tool count. **That is a harness
being honest about its own cost**, and it is the only such figure found: a field
survey the same day returned one overhead number across eleven harnesses, and
that number turned out to be THIS REPO'S OWN Aider measurement attributed to a
different tool.

### A correction to a figure this repo has been quoting

F105's "761 tokens" for Aider has been repeated all session as though it were a
fixed property. Aider's own accounting on this task reports **2.5k sent**, and
the wire carries 11,121 B. These are not contradictory - F105 measured a
different task - but **Aider's overhead scales with the repo map and the files
in the chat**, and quoting 761 as a constant is wrong. Any future citation names
the task.

### What stage 1 does NOT establish

- **Admissibility is not effectiveness.** Fitting is necessary and not
  sufficient; a harness that fits may drive the model badly (F87's shape,
  applied to clients). No recommendation is made here.
- **One task shape**, one small repo, one turn.
- **Versions drift** and are stamped: Aider `0.86.2`.
- **Nothing about IDE-embedded clients** (Cline, Roo, Continue), which cannot be
  driven headlessly here. `continue` on PATH is the SHELL BUILTIN, not the
  harness - a false positive caught during inventory.
