## E63: does gpt-oss-120b hold up at DEPTH, or only in single turns? (2026-08-19, pre-registered before any run)

**Prerequisite 2 of the R&D programme.** E62 closed capability: 12/12 on
L3-hard, reproduced bit-for-bit. F88 states plainly what that does not buy - a
deterministic arm reproduces its errors as faithfully as its successes, so
nothing about robustness follows from it. E57 is the instrument that already
caught this exact illusion once: **Qwen3-8B held 5 of 5 anchors with its own
answer in the history and lost 4 of 10 when the questions were held out.**

**Design: E57's crossover, unchanged.** Two runs over the same L4 pack,
`heldout-ab` and `heldout-ba`, each question asked exactly once per run, so the
model's own earlier answer is never in the context it re-reads. 18 turns, 13
graded, probes split shallow / recent / deep.

**Serving assumption, stated because it is a choice.** `--thinking default`,
`--ctx 32768`, `--max-tokens 5120`, matching E57's arms on context and budget
and matching E62 on the reasoning setting. `default` is the setting under which
this model scored 12/12; changing it here would confound depth with reasoning
budget. The comparison arms (Qwen3.8-27B at `low`, Qwen3-8B, workhorse) are
already run and are NOT re-run.

### Predictions

1. **PRIMARY: gpt-oss-120b scores 12-13/13 on each arm** with **no deep
   degradation** - deep probes within 1 of shallow probes. It matched the dense
   27B exactly on L3-hard, and the 27B is the arm that held 10/10 shallow and
   10/10 deep.
2. **`wrong_document` is 0 on both arms.** It has been 0 on every arm of every
   conversation experiment so far (F74's conversational analogue), and this
   model was 0 over-claims on L3-hard.
3. **Both arms complete with no `transport_failed`.** Two further loads; four
   consecutive clean ones precede them.
4. **Wall per arm under 400s**, from E61's 2.7x speed advantage over the dense
   27B, whose E57 arm was 695.9s.

**Falsifiers, and what each means:**

- **Deep probes 2 or more below shallow on either arm** - the capability is
  single-turn only, gpt-oss-120b joins the 8B in F83's amendment, and it is
  disqualified as a reviewer over a long context regardless of its L3-hard
  score. **This is the result that would most change the programme**, and it is
  a live possibility: ~5.1B active parameters is the 8B's order of magnitude,
  not the 27B's.
- **Any `wrong_document`** - the first non-zero in this programme, and it would
  make the model unsafe on a folder of similar agreements, which is the actual
  deployment shape.
- **A decode hang on either load** - recorded as instrument failure, NOT a
  capability score (the E61 rule stands), and the hang denominator becomes 1 in 6
  or 1 in 7 rather than 1 in 5.

**Cost.** Two arms, two 59.03 GiB loads, no cloud spend. Near-edge for the
amdgpu suballocator deadlock: box quiet, run attended.

### E63 RESULT: depth is NOT the weakness - the failure is a flat, position-independent off-by-one (2026-08-19 08:14)

**All four predictions held.** Both arms clean, no `transport_failed`, no hang.

| | arm ab | arm ba |
|---|---|---|
| score | 12/13 | 12/13 |
| wall | 234.9s | 215.4s |
| shallow | 5/5 | 4/5 |
| recent | 3/3 | 3/3 |
| deep | 4/5 | 5/5 |
| `wrong_document` | 0 | 0 |
| `accepted_false` | 0 | 0 |

**Joined across the crossover, which is the measurement:**

```
shallow 9/10  ->  deep 9/10   at 22,066 of 32,768 tokens (67.3%)
degraded: none    improved: none    wrong_document at depth: none
recent probes: 6/6
```

**The single failure is the same question in both positions, with the same wrong
answer.** `P3` is `off_by_calendar` shallow AND deep - **15 September 2026**
where the answer is 14 September 2026. Because the crossover asks each question
exactly once per run and swaps which run asks it early, a question wrong in both
positions is wrong independently of depth. **Depth is exonerated.**

**What the error actually is, and it is not a retrieval failure.** `P3` plants
three candidate trigger dates in `CHRON` on purpose - the breach, the discovery,
and the earlier contract - and STAT-LIM paragraph 2 names which one governs.
Choosing another grades as `wrong_trigger`. gpt-oss-120b did **not** do that: it
selected the correct trigger and then landed on the `+1 day` trap. It read the
documents correctly and computed the last day of the period wrongly, by one day -
an inclusive/exclusive boundary error on a limitation period.

**Every other arm gets this question right**, at both depths: Qwen3.8-27B,
Qwen3-8B, and the workhorse all answer 14 September 2026 deep. (The workhorse
fails it *shallow*, as `wrong_trigger` - a different error entirely, and the
reason F80's tiering says use it to read a contract and never to work out a
date.) gpt-oss-120b is the only arm to make this particular mistake.

**More reasoning did not buy correctness, and this is the datum prerequisite 4
wants.** The same wrong answer cost **1,679** reasoning characters shallow and
**5,367** deep - 3.2x the reasoning for an identical wrong output. Reasoning
volume is not evidence of reasoning quality, and a commitment-latency proxy built
on reasoning length must not assume otherwise.

**Predictions, scored:**

1. 12-13/13 per arm with deep within 1 of shallow - **HELD**, and more strongly
   than registered: the gap is 0, not 1.
2. `wrong_document` 0 on both arms - **HELD**
3. no `transport_failed` - **HELD**
4. wall per arm under 400s - **HELD** at 234.9s and 215.4s

**Hang denominator: one in seven loads** on 2026-08-19 (failed L3 run, smoke,
bisect, E61 retry, E62, E63 ab, E63 ba). Six consecutive clean loads now. Still
no rate, still unexplained, still disqualifying for unattended use.
