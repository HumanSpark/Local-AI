## E132 - the document banks on the new runtime, and what the medium default costs (2026-09-07)

Six arms through the live gateway after the runtime upgrade and the effort flag.
Every banked control for this model on l3/l4/l5 used `thinking=low`, so `low` is
the like-for-like arm and isolates the RUNTIME; the default arm is what
production scores now. Greedy, `max_tokens 4096` - the controls' own budget.

| bank | control at `low` | today `low` | today default (`medium`) |
|---|---|---|---|
| l5 | 23/24, fails `R09` | 22/24, fails R09-shaped + **`R10` truncated** | 22/24, fails **`R09`** + **`R10` calendar** |
| l4 | 14/15, fails `N2` | **14/15, fails `N2`** | 13/15, fails `N2` + **`P3`** |
| l3 (9 distractors) | 12/12 | **12/12** | **12/12** |

### The runtime is clean

**l4 and l3 reproduce their controls exactly at `low`, item for item.** l4 fails
`N2` with `off_by_calendar`, which is what `e91-B`, `e54b` and `e93-BASE` all
did; l3 fails nothing, as its control did. That is [[F117]]'s standard met with
the item recorded rather than inferred.

**The single difference anywhere is `R10` on l5**, which the control answered
correctly ("16 June 2027") and which now fails in both arms - truncating at
`low`, wrong date at `medium`.

### R10 is not attributable from this run, and three variables could explain it

The control ran a raw server at `-c 16384 -fa on`. The gateway runs `-c 49152
-fa on -ctk q8_0 -ctv q8_0 -ub 2048`. So the runtime, the KV cache precision and
the context/batch settings all differ at once.

**The KV hypothesis is the one worth testing, and [[F110]] undercuts itself here.**
F110 records "q8_0 is free, 4-bit is a 5.6% cliff" - and says in the same line
that **100 perfect retrievals measured none of it**. A measure at ceiling cannot
detect a small cost, so "free" rests on a saturated instrument, and `R10` is the
longest, hardest calendar item on either bank - exactly where a small cost would
appear first.

**Against that hypothesis:** l4 and l3 run through the same q8_0 KV and reproduce
perfectly. A general KV cost would show there too. A length-related effect on the
single longest item now looks likelier than a broad one.

**The cheap test:** l5 on the new build, raw, with and without `-ctk/-ctv q8_0`,
and see whether `R10` returns. Needs a maintenance window for a quiet GPU.

### What the `medium` default costs, stated at its real strength

**One item, on one bank of three.** l4 drops 14 -> 13 (`P3`, a statutory-period
item, `off_by_calendar`). l5 is level at 22 and l3 is level at 12.

An earlier reading of this session called it a pattern across two banks. It is
not: l5 tied on score and only changed which way `R10` failed. **One bank of
three, one item.**

These are greedy runs at temperature 0, so the l4 difference is real for this
configuration rather than sampling noise. One item is still one item.

### The trade this creates, and why `medium` is still defensible

The banks point opposite ways:

| axis | `low` | `medium` |
|---|---|---|
| expert coding tier (E42) | 5/8 | **7/8** |
| runaway generations at the old `xhigh` default (F140) | not measured | fixes 11 of 18 |
| l4 document dates | **14/15** | 13/15 |
| l5, l3 | level | level |

**No single server-wide default is right for both.** `medium` buys two of eight
on coding and removes the runaway failure mode; it costs one of fifteen on
contract dates.

**Keeping `medium` is the better default on this evidence**, because the coding
gain is larger and the runaway fix is a failure mode rather than a score. Any
caller doing date-critical document work can send `reasoning_effort: low` per
request, which E129 confirmed still overrides in production. That is the routing
guide's shape already - per-task routing rather than one global setting.

### Cost and limits

Six arms, 102 requests, roughly two hours through the gateway.

Run through the gateway deliberately (see E131), so these are a regression signal
and not bench figures, and the wall times are not comparable to the controls'.
**The l5 `low` arm predates the per-item logging** added mid-run, so its single
graded failure is recorded as an `off_by_calendar` whose id was not captured; the
controls' one failure was `R09` and the default arm's was `R09`, so it is very
likely the same item, and it is not asserted.
