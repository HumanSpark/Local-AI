## E125 PRE-REGISTRATION - what a user actually waits, for both workhorse candidates (2026-09-07)

**Registered before the run.** `results/raw/e125` does not exist.

### Why this experiment exists

The swap case now has accuracy (E121, E124) and raw throughput (E122). It is
missing the number that decides an ALWAYS-LOADED interactive slot: **how long a
person waits for an ordinary reply.**

E122's `tg128` says Nemotron is 32% slower per token. E121 says something much
larger in practice - **0.36-2.85 s per item for the workhorse against 9-268 s
for Nemotron** - because Nemotron emits far more tokens before answering. A 32%
throughput gap and a 10x wall-clock gap are different decisions, and only the
second is what a user experiences.

| | |
|---|---|
| **which success question** | what the swap costs in perceived latency |
| **uncertainty reduced** | whether Nemotron is usable in an interactive slot at all |
| **decision that changes** | whether the swap proposal recommends adoption, or adoption only for batch work |

### Design

The nine short turns from E116 - trivial, factual, light-reasoning, generative -
run against both models, greedy, `--max-tokens 4096`, one server each, quiet GPU,
build `daef7b6` for both so the comparison is model-to-model.

Effort is not set for either: E123 measured it INERT for both.

### Predictions, each naming the FIELD is scored against

| # | prediction | scored against |
|---|---|---|
| 1 | **HEADLINE: the wall-clock gap is far worse than the 32% throughput gap** | Nemotron median wall / workhorse median wall **> 3.0** |
| 2 | and it is driven by tokens emitted, not by speed | Nemotron median completion tokens / workhorse median **> 3.0** |
| 3 | the workhorse stays interactive | workhorse median wall **< 5 s** |
| 4 | Nemotron does not stay interactive on every turn | Nemotron **max** wall **> 20 s** |

**P1 and P2 together are the point.** If both hold, the swap is an accuracy-for-
latency trade and the proposal must say so in seconds, not in percentages.

### Registered decision rule

| observed | action |
|---|---|
| P1 and P2 hold | the proposal recommends the swap **for document/batch work only**, and says plainly that the interactive slot pays multiples of the current wait |
| P1 fails, ratio <= 3 | the latency cost is modest and the swap can be recommended outright on the accuracy case |
| P3 fails | the workhorse is not interactive either, and the comparison is between two slow models - re-frame before proposing anything |

### What this cannot establish

- Nine turns, one run each, no concurrency. The production relay batches, and
  batching changes both numbers.
- Nothing about quality on these turns; E116 established that a short-turn bank
  measures cost, not correctness.

## E125 RESULT - 5.65x the wait, and both stay interactive. P4 falsified. (2026-09-07)

Nine short turns, both models, greedy, quiet GPU.

| | workhorse | Nemotron |
|---|---|---|
| median wall | **0.46 s** | **2.60 s** |
| max wall | 1.66 s | **4.12 s** |
| median completion tokens | 28 | 105 |
| total wall, nine turns | 4.9 s | 25.3 s |

| # | prediction | outcome |
|---|---|---|
| 1 | HEADLINE: median wall ratio > 3.0 | **held** - 5.65 |
| 2 | driven by tokens, ratio > 3.0 | **held** - 3.75 |
| 3 | workhorse median < 5 s | held - 0.46 |
| 4 | Nemotron max wall > 20 s | **FALSIFIED** - 4.12 s |

### P4's failure changes the recommendation, and the registered rule would have overstated it

The registered rule said P1+P2 holding means recommending the swap **for
document/batch work only**. **That is now too strong**, and applying it
mechanically would have produced a wrong recommendation.

P4 predicted Nemotron would blow past 20 s on some short turn, extrapolating from
E121's 9-268 s per item. It does not: **its slowest short turn is 4.12 s.** Those
long E121 waits came from document tasks with large packs, not from short turns.

So the honest statement is both numbers at once: **Nemotron costs 5.65x the
median wait, and its worst short turn is still 4.12 seconds.** A 5.65x multiple
sounds disqualifying; 0.46 s against 2.60 s does not. Relative and absolute point
opposite ways here, and quoting either alone misleads.

**P2 explains the mechanism:** the gap is 3.75x more tokens emitted, not slower
generation. E122 measured the raw speed gap at 32%.
