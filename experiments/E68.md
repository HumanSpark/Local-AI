## E68 - PREREGISTRATION: does OFFERING an irrelevant tool cost accuracy? (2026-08-19)

**Registered BEFORE any run.** No arm has been run at the time of writing. The
runner change is made and verified drift-free (E67's `l4-date` path builds a
byte-identical 10,029-char pack and the same six ids); no E68 model call exists.

### Why this is the experiment with production consequence

E67/F93 found that gpt-oss-120b regressed on `N2` **while making no tool call**,
and the three-condition control traced it to the `tools` field rather than the
sentence announcing it: under `--jinja` the schemas are rendered into the prompt,
so `add_period` appeared 14 times in the tools run's prompts and 0 times in the
preamble-only run's.

If that generalises, it is not a bench curiosity. **Any sparkrouter route that
offers tools by default is paying for them on every request, including the 91.3%
of real traffic that is ordinary chat and needs no tool at all.** E67 could not
speak to that: all six of its questions were date questions the tool was FOR.

### Design

Same runner, same three conditions, **a question set the date tool is irrelevant
to**. L1: 20 questions, 10,741-char pack, graded by `grade_answer`. Nothing in L1
asks for a date calculation, so any movement is the cost of OFFERING a tool, not
of using one.

| condition | preamble | `tools` in payload |
|---|---|---|
| control | no | no |
| preamble-only | yes | no |
| tools on | yes | yes |

**Model: the workhorse Qwen3-30B-A3B first**, because it is the production
resident that carries 91.3% of real requests, and because L1 is the tier where it
has room to move in either direction. gpt-oss-120b follows if the workhorse shows
an effect.

**L1 is a PROXY for ordinary traffic, and a declared one.** Real chat has no
objective grader, so the closest graded stand-in is a document-QA tier the tool
does not serve. A null result on L1 does not prove tools are free on chat; a
positive result does not prove the size of the effect on chat.

### Predictions, each naming the FIELD it is scored against

| # | prediction | field |
|---|---|---|
| 1 | `preamble-only` matches `control` exactly - the sentence is not the mechanism, as in E67 | top-level `correct`, both runs |
| 2 | `tools on` is **strictly lower** than `control` | top-level `correct`, both runs |
| 3 | The drop is **1 to 3 questions** of 20, not larger | `correct` difference |
| 4 | The workhorse **calls the date tool at least once** on a tier that needs no dates - an unnecessary call is itself a defect | `total_tool_calls`, treatment run |
| 5 | At least one regressed cell shows `no_call`, i.e. the harm arrives without the tool being used | per-result `class` and `outcome`, both runs |

**Prediction 2 is the one I expect to be wrong about most easily.** E67's
regression was a single cell on a model that barely engaged the tools. The
workhorse engaged heavily (13 calls on 6 questions), so on a tier with no dates
it may either call constantly and derail, or ignore the tools entirely and score
identically. **A null result is a real and useful outcome here** - it would scope
F93 to the model rather than to the mechanism.

### Decision rule, registered now

- `tools on` < `control` on L1 -> the F93 mechanism is **not** confined to date
  questions, and "tools always on" is a live production defect for that model.
- `tools on` == `control` **and** `total_tool_calls` is 0 -> the model ignores
  irrelevant tools and the cost is confined to routes where the tool is
  plausibly relevant. Report as scoping, not as a null.
- `tools on` == `control` **with** calls made -> the model wastes calls without
  losing accuracy. A latency and cost finding, not a correctness one; measure
  wall time before concluding it is free.
- `tools on` > `control` -> unregistered direction; report and do not explain it
  away.

## E68 - RESULTS: offering an irrelevant tool is NOT free, and the direction is model-specific (2026-08-19)

Preregistration immediately above, banked in `e5e0168` before any run. L1, 20
questions, 10,741-char pack, no date question anywhere in it. Temperature 0.

| model | control | preamble-only | tools on | tool calls |
|---|---|---|---|---|
| workhorse 30B-A3B | **14/20** | 13/20 | **11/20** | **68** |
| gpt-oss-120b | **20/20** | **18/20** | **20/20** | **0** |

### The workhorse: -3 of 20, and the mechanism is NON-TERMINATION

Outcome counts move from `{correct 14, partial 2, wrong 4}` to
`{correct 11, format_error 5, partial 2, wrong 2}`. **The five `format_error`
cells are the whole story: they did not answer wrongly, they did not answer at
all.** `R4` and `C1` both ran to `rounds=6` - the registered `max_rounds` cap -
having made 6 tool calls each and never emitted a parseable answer.

**68 tool calls on a tier with no dates in it.** A sample, all from questions
about retainers, liability caps and notice periods:

```
R1: date_diff(start=2024-03-01, end=2024-04-01, unit=days) -> 31
R1: add_period(date=2024-03-01, months=1)  -> 2024-04-01
R1: add_period(date=2024-03-01, years=1)   -> 2025-03-01
R2: date_diff(start=2024-03-01T00:00, end=2024-03-31T00:00, unit=days) -> 30
S1: add_period(date=2025-01-01, months=0, days=0, hours=0) -> raises
```

The last one is the tool refusing a no-op it was right to refuse. The model is
reaching for a calculator on questions that contain no arithmetic.

**Registered predictions: 2, 3, 4 and 5 held; 1 falsified.** `tools on` is
strictly lower (11 < 14); the drop is 3, inside the registered 1-3 band; the
model called the tool on a dateless tier, emphatically; and `U4` regressed with
`no_call`, so harm arrives without the tool being used. **Prediction 1 was that
`preamble-only` would match control exactly, as it did in E67. It did not** -
`C1` moved from a correct 32,960,000 to 33,060,000. Four lines of text saying
tools exist changed an arithmetic answer at temperature 0.

### gpt-oss-120b: the opposite pattern, and it inverts the E67 reading

Offering the tools costs **nothing** (20/20, and it made zero calls - it simply
ignored them). The **preamble alone** costs two questions (18/20).

So across the two experiments the effect has no consistent direction:

| | E67 date questions | E68 L1 questions |
|---|---|---|
| workhorse | preamble n/a, tools **+4** | preamble **-1**, tools **-3** |
| gpt-oss-120b | preamble **0**, tools **-1** | preamble **-2**, tools **0** |

**Every cell of that table is a different answer.** Tools help the workhorse on
questions the tool is for and hurt it badly on questions it is not; they cost
gpt-oss a point on date questions and nothing on L1, while the mere announcement
costs gpt-oss two points on L1 and nothing on dates.

### What E68 establishes

**The decision rule fires: the F93 mechanism is not confined to date questions,
and "tools always on" is a live production defect for the workhorse** - the model
that serves 91.3% of real traffic. A relay route that offers tools by default is
paying up to 3 questions in 20 on requests that need no tool, and paying it as
non-termination rather than as a wrong answer, which is the more expensive
failure for a user waiting on a response.

**What it does not establish.** L1 is a declared PROXY for ordinary traffic - it
is document QA, not chat, and real chat has no objective grader. The `rounds=6`
cap means the two runaway cells are "did not reach an answer within six rounds",
not "could never"; a higher cap trades format errors for latency and was not
tested. n=1 per cell on a deterministic pair, so these are exact for this item
set and carry no interval for unseen items. And gpt-oss is at 20/20 on L1, so
that arm is at ceiling and could not have shown a tools-driven drop even if one
existed.
