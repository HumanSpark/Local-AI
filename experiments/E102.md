## E102 PRE-REGISTRATION - does the GSQ-RCO IQ3_S quant hold Q4_K_M quality on the same model? (2026-09-04)

**Registered before either arm runs.** No L5 result file for either arm exists
at the time of writing.

### Why this experiment exists

| | |
|---|---|
| **which success question** | production serving - a 4.7 GiB saving on the `smart` slot would change what fits resident |
| **uncertainty reduced** | whether a ~3-bit quant of our incumbent is measurably worse at knowledge work |
| **decision that changes** | whether the asymmetric three-model config (F135/F138) can hold a larger context, or a fourth model, in the same envelope |

### The pair, and why it is clean

| | incumbent | challenger |
|---|---|---|
| file | `Qwen3.8-27B-Q4_K_M.gguf` | `Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp.gguf` |
| bytes | 16,810,714,336 | 12,120,016,960 |
| arch | `qwen35` | `qwen35` |
| trained ctx | 262,144 | 262,144 |
| sha256 vs pinned oid | - | MATCHES (`58fd8267...`) |

Same architecture, same trained context, same base model. **The pair differs by
the quantisation recipe and nothing else**, which is what makes a difference
attributable. Probed with `tools/gguf_ctx_probe.py` before registration, per
F124 - model metadata can falsify an arm before it is run.

### The instrument, and its known saturation

`tools/run_ps_eval.py --tier l5`, 24 items, 12 per band, gated by
`tools/validate_ps_eval_l5.py`. Config matched to E78's registered arm: `-c
16384`, `-fa on` (passed EXPLICITLY via `--server-extra`, which is the only way
it reaches the server - see E101 Amendment 1, where assuming it was a default
was a real defect), `--thinking low`. **Both arms run fresh in this session on a
QUIET GPU** rather than comparing against E78's banked numbers - E78 breached
Rule 9 and its wall times are VOID, so its timings cannot be a comparator.

**The incumbent scores 23/24 on this bank (band R 11/12, band E 12/12, E78).
That is near the ceiling, and it is the central limitation of this design.**
The bank can detect the challenger falling and cannot detect it rising. That is
acceptable for the question actually asked - *does the small quant degrade?* -
and it is stated here so no one later reads a tie as evidence of equivalence.

### Predictions, each naming the FIELD it is scored against

| # | prediction | scored against |
|---|---|---|
| 1 | the incumbent reproduces its own banked score | incumbent `total correct` **>= 21 of 24** (E78 got 23; this allows the two-item order effect E82 measured) |
| 2 | **DISCRIMINATING: the quant costs something on reasoning** | incumbent `band R correct` minus challenger `band R correct` **>= 2** |
| 3 | the evidence band does not separate them | absolute difference in `band E correct` **<= 1** |
| 4 | the quant does not induce over-claiming | challenger `over_claim` **<= 1** of the 4 underspecified items |
| 5 | the graders hold | `format_error` **= 0** across all 48 items |
| 6 | the smaller file is faster to first token | challenger median `wall_s` **<** incumbent median `wall_s` |

### Registered decision rule, tie-break included

| observed | action |
|---|---|
| P2 holds | the quant costs measurable reasoning quality. Report the size saving as PAID FOR, not free |
| P2 fails and P3 holds - the arms are within 1 on both bands | **NOT equivalence.** Report as "no difference detected at n=24" with the Wilson interval, and run the SECOND BANK below before any recommendation |
| P1 fails | the incumbent did not reproduce. Nothing may be concluded about the challenger; audit the build and conditions first |
| any `format_error` | audit the grader before reading any score |

### The second bank, registered now so it is not a post-hoc choice

If P2 fails, run `tools/run_coding_eval.py --task-set core` (15 tasks) on both
arms, greedy, `--thinking medium`. **Registered in advance because "the null
was uninteresting so we went looking elsewhere" is exactly the move this
register exists to prevent.** Its scoring: challenger `pass` count minus
incumbent `pass` count, difference of **>= 3 of 15** counts as a detected
degradation.

### What this cannot establish

- **24 items cannot establish equivalence.** A null is "no difference
  detected", never "the same". Any report of a null quotes the Wilson interval
  and the n.
- **One quant of eight in that repo.** IQ3_S-mtp is the variant the community
  report named and the largest of the four recipes; IQ2_XS may behave entirely
  differently and is not tested.
- **Nothing about the MTP head.** The `-mtp` file carries one; it is not
  enabled at serve time here, so this compares weights, not speculative decode.


## E102 RESULT - the 3-bit quant is indistinguishable from Q4_K_M on this bank, 4.7 GiB smaller and 34% faster. PREDICTION 2 FALSIFIED. (2026-09-04)

Two arms, 24 items, tier `l5`, `-c 16384`, `-fa on` (passed explicitly and
verified in the server command line), `--thinking low`, quiet GPU, build
`b10435`, kernel `7.0.0-29-generic`.

| arm | total | band R | band E | only miss | median/item | on disk |
|---|---|---|---|---|---|---|
| `Qwen3.8-27B-Q4_K_M` | 23/24 | 11/12 | 12/12 | `R09` off_by_calendar | 40.93s | 15.66 GiB |
| `Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp` | 23/24 | 11/12 | 12/12 | `R09` off_by_calendar | **26.90s** | **11.29 GiB** |

**Separation: zero points on both bands, and the same single failing item.**

### The incumbent reproduced E78 ITEM FOR ITEM, which is what licenses the comparison

F117's requirement. Both files re-graded through `tools/score_l5_bands.py` in
one invocation, so the ruler is identical on both sides:

| run | date | total | band R | band E | miss |
|---|---|---|---|---|---|
| E78 `l5-pilot-qwen38` | 2026-08-28 | 23/24 | 11/12 | 12/12 | `R09` |
| E102 `e102-incumbent-q4km` | 2026-09-04 | 23/24 | 11/12 | 12/12 | `R09` |

The scorer surfaced why the RAW files disagree: E78 banked `R09` as `wrong` and
the current grader re-grades it to `off_by_calendar`. **Comparing banked
outcomes would have manufactured a difference that does not exist** - which is
the defect the re-grading behaviour was built for.

⚠️ **The item this turns on is a known coin-flip.** E82 measured `R09` as one of
four items whose verdict is NOT stable across prompt orders (`correct` /
`off_by_calendar`). Reproducing it exactly is reassuring and is NOT proof of
determinism.

### Scoring

| # | prediction | outcome |
|---|---|---|
| 1 | incumbent total >= 21 of 24 | **HELD** - 23, and item-identical to E78 |
| 2 | **DISCRIMINATING: quant costs >= 2 on band R** | **FALSIFIED** - 0 |
| 3 | band E differs by <= 1 | **HELD** - 0 |
| 4 | challenger `over_claim` <= 1 of 4 | **HELD** - 0 |
| 5 | `format_error` = 0 across 48 | **HELD** - 0 |
| 6 | challenger median wall < incumbent median wall | **HELD** - 26.90s vs 40.93s, **34% faster** |

### Registered decision rule - which branch fired, and what it forbids

Registered: *"P2 fails and P3 holds - the arms are within 1 on both bands ->
**NOT equivalence.** Report as 'no difference detected at n=24' with the Wilson
interval, and run the SECOND BANK before any recommendation."*

**That is the branch, and the second bank is running.** It was registered before
this null appeared, so following it to a different instrument is not a post-hoc
choice.

**No difference detected at n=24.** Both arms 23/24; the interval on a 23/24
proportion is wide and 24 items cannot establish equivalence. **A tie here is
not a finding that the quant is as good - it is a finding that this bank cannot
tell.** See E103, where the same bank also failed to separate a different base
model, and F142.

### What is NOT claimed

- **Not equivalence.** See above; the second bank exists because of it.
- **One quant of eight in that repo.** IQ2_XS may behave entirely differently.
- **Nothing about the MTP head**, which is present in the file and not enabled.
- **The speed figure is real and separately measured**: 26.90s vs 40.93s median
  over 24 items on a quiet GPU. Unlike E78's, these wall times are valid.
