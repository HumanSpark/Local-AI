## E43: the closed-record legal matters - all thirteen, against an instrument that already discriminates (2026-08-15, pre-registered before any run)

**Why this exists.** Owner instruction: run the legal matter benchmarks, ALL
matters, and raise the token budget very significantly (5-15x).

**This is the first knowledge-work instrument today that was NOT built today.**
`spikes/closed-record/matters/` holds thirteen matters written between
2026-08-11 and 2026-08-12, with keyed scoring rather than a judge. Unlike L1
and L2 - both of which Qwen3.8 exhausted on 2026-08-15 at 20/20 and 12/12 -
this corpus **already separates models**: F60 records m11-limitation-clocks at
**6/15** and m13-interest-two-clocks at **7/15** against m08's 15/15. A corpus
that hard is the obvious next probe, and it cost nothing to build.

F60 also states the theory of what makes a matter discriminate: a period that
must be **WALKED**, or two competing bases - not merely a second base that is
selected. That theory is what these thirteen were built to.

**Four harness defects fixed before any arm ran, each of which would have
corrupted the result.**

1. **`--max-tokens` default 2000.** Owner's instruction was 5-15x; this run
   uses **24,576 (12x)**. The old default is far below what this model spends
   before it answers - E42 measured 6,832 completion tokens for twelve short
   knowledge answers at the template default - so 2000 would truncate and make
   the corpus look harder than it is. That is F20 exactly.
2. **The lifecycle script pointed at `llama.cpp/build/bin/llama-server`, a
   3 July binary.** Every other 2026-08 result in this repo uses the b10435
   worktree build, and F63 measured that move at about +3.3% tg. Mixing builds
   across a comparison is a config confound (Rule 8). Now defaults to b10435
   and is overridable by `SPARKBENCH_SERVER_BIN`.
3. **The server was started without `-v`,** so the Rule 3 full-offload gate had
   no evidence to read - and Rule 3 FAILS on zero evidence rather than passing.
4. **`pgrep -f "port 8100"`** in the cleanup check self-matches through the
   invoking shell and reports a phantom occupant. Now `pgrep -x llama-server`.
5. **`--timeout` defaulted to a FIXED 600s** (found 2026-08-15, before arm A
   ran). This is the E33-void defect exactly, in a fourth runner: raising
   `max_tokens` to 24,576 while a fixed request timeout stays put means every
   generation that uses the extra budget dies as `transport_failed` and
   produces no data. At 6 tok/s, 24,576 tokens needs **4,396s**; 600s would
   have killed the long matters, and F60 says the long matters are the ones
   that discriminate. So the arm most likely to fail was the arm the
   experiment exists to run. `run_matters.py` now carries the same
   `resolve_request_timeout()` as the other three runners - derived from
   `max_tokens`, warning rather than overriding when a caller sets a shorter
   value deliberately. The output JSON now also records `thinking` and
   `request_timeout`, because E43's arms differ ONLY by thinking level and a
   file that does not carry it can be told apart from its sibling only by its
   label (Rule 8).

   Verified by unit-level check, not a live run: derived 4,396s at 24,576 and
   633s at the old 2,000-token default, with the warning firing on an explicit
   600s. **A live smoke test was NOT run** - llama-server is occupied by the
   E42 writing row and Rule 9 permits one GPU consumer, so the first live
   exercise of this path is arm A itself.

   Class sweep: `run_ps_eval.py`, `run_coding_eval.py` and
   `run_writing_eval.py` already derive their timeouts.
   `tools/run_longctx_eval.py` pins `max_tokens` at 256 against a 3,600s
   timeout, so it is not the same defect.
   `spikes/eval-pilot/judge_pairwise.py` is a latent instance - 900s fixed
   against a 1,400-token default needing 533s - adequate at its default,
   under-provisioned only if someone raises the budget. Left alone: it is
   judge-based and this programme is judge-free.

**The existing baselines are NOT comparable and are not used as such.**
`results/closed-record/full-*.json` hold ten-matter runs for the workhorse,
Mistral-24B and GLM-4.7-Flash, but at `max_tokens 2000` on the July build.
Comparing a 24,576-token Qwen3.8 run against them would be exactly the
like-for-like failure that measurement-integrity rules exist to prevent, so
the incumbents are RE-RUN here at identical settings.

**Config.** `tools/run_closed_record.sh`, llama-server b10435, `-c 32768`,
`-np 1`, `--jinja`, `-v`, temperature 0, `max_tokens 24576`, 1 rep, all 13
matters. Prompts are small (483-854 tokens), so the budget is entirely about
what the model generates before it commits.

Bands are set high, deliberately: my registered bands sat below the measured

experimenter rather than a run of bad luck.**

2. **Qwen3.8 beats every incumbent's total.** This is the discriminating

3. **`low` and `xhigh` score within 10 points of each other** (of 195). E42

and it becomes the third instrument exhausted in a day. The honest report then
is that no available knowledge-work instrument bounds this model, which is a
finding about the instruments rather than a measurement of the model.

### E42 writing row, partial: thinking IMPROVES compliance and DEGRADES honesty

Two cells of four. Recorded now because the direction contradicts the
knowledge row, and because it exposes a conflict between two things I
registered at different times.

| | off | low |
|---|---|---|
| clean drafts | 2/7 | **4/7** |
| `fabrication_rate` | **0.000** | 0.143 |
| `negative_retention` | **1.00** | 0.80 |
| empty responses | 0 | 1 |
| wall | **225.2s** | 2,546.4s |
| median/item | **33.3s** | 338.0s |

Task by task, `off` -> `low`: two length overshoots became clean
(`exec_summary`, `persuasive_pressure`), and three became WORSE -
`plain_english` invented two figures, `book_passage` dropped an unfavourable
finding, and `client_email` returned nothing at all.

**The empty response is a model behaviour, not a harness fault.**
`finish_reason: stop`, 3,593 completion tokens of a 16,384 budget, 13,635
characters of reasoning, and empty content. It thought for five minutes about
a 150-word email and emitted no email. A silent empty answer after five
minutes is worse in production than a wrong one, because nothing signals that
it happened.

**THE CONFLICT, STATED RATHER THAN RESOLVED BY PICKING THE METRIC I PREFER.**
E42 AMENDMENT 2's decision rule ranks on "score", and for the writing row the
score is fully-clean drafts. By that rule `low` wins, 4 against 2. But E40's
registration named `fabrication_rate` and `negative_retention` as the HEADLINE
metrics for writing, on the argument that an invented figure or a dropped
unfavourable finding makes a draft unpublishable while a word count makes it
an edit. By those, `off` wins outright: no fabrications against one, full
retention against 0.80, no empty responses against one.

Both were registered before any data existed and they disagree. I am not
switching to whichever now flatters a conclusion. The row will be reported
with both readings, and the routing recommendation has to say which failure a
user would rather have - a draft that needs trimming, or a fluent draft
containing a figure that is not in the source.

**What this does NOT yet show.** Two cells of four. `medium` and `xhigh` may
recover the honesty metrics, in which case `low` is a local dip rather than a
trend, and the sample is one task set of seven items. The knowledge row found
thinking strictly beneficial; this row so far finds it a trade. That
divergence across task types is exactly what the owner asked to be measured
and is the reason the matrix has three rows rather than one.

### E42 writing row, third cell: `medium` DISSOLVES the conflict, and `low` was a dip

The `medium` cell arrived and the caveat above was the right one to have
written: `low` is a local dip, not a trend.

| | off | low | **medium** |
|---|---|---|---|
| clean drafts | 2/7 | 4/7 | **6/7** |
| `fabrication_rate` | **0.000** | 0.143 | **0.000** |
| `negative_retention` | **1.00** | 0.80 | **1.00** |
| empty responses | **0** | 1 | **0** |
| length violations | 5 | **0** | 1 |
| style violations | 0 | 0 | 0 |
| wall | **225.2s** | 2,546.4s | 4,277.6s |
| median/item | **33.3s** | 338.0s | 498.16s |

**`medium` dominates both other cells on every quality field at once.** It
matches `off`'s perfect honesty scores and beats `low`'s compliance. There is
no longer a metric under which `off` or `low` wins, so **the conflict
recorded above does not need the owner's casting vote** - AMENDMENT 2's rule
and E40's headline metrics now select the same cell. I am recording that it
dissolved rather than deleting the conflict, because it was real when written
and the reasoning that kept both readings alive is what made this cell
interpretable.

**The three tasks `low` broke are all repaired at `medium`.**
`plain_english` no longer invents figures (it is the single remaining miss, at
**201 words against a 120-200 band** - one word), `book_passage` retains the
unfavourable finding F-B, and `client_email` produces an actual email instead
of five minutes of silence. `correspondence`, `durable` and `summary` all go
0/1 -> 1/1.

**Reasoning level is NOT monotonic on writing quality.** `low` is worse than
BOTH its neighbours on honesty: it is the only cell in the row with a
fabrication, the only one that dropped a negative finding, and the only one
that returned an empty response. A two-point sweep that happened to sample
`off` and `low` would have concluded that thinking degrades honesty; a sweep
of `off` and `medium` would have concluded thinking is free of cost. Both
conclusions would have been wrong, and this is the argument for sweeping every
level rather than the endpoints.

**The owner's hypothesis is VINDICATED on this row, having been falsified on
the knowledge row.** He predicted `medium` as the cheapest level giving high
quality. On knowledge work the plateau starts at `low` and `medium` is
overspend; on writing, `medium` is the first level that is actually clean.
**The cheapest adequate level is task-dependent**, which is a stronger and
more useful result than either row alone, and it is why F69's scope is
deliberately confined to knowledge work.

**The cost is not small and is not hidden.** `medium` is **19x** `off`'s wall
time (4,277.6s against 225.2s) for +4 clean drafts, at a 498s median per item.
Nothing in this row is interactive: no level reaches a 30s median. Drafting on
this model is a batch activity at any setting that produces usable output.

**Still open:** the `xhigh` cell. If it also scores 6/7 with clean honesty
metrics, `medium` wins on cost alone; if it scores higher, the row's
recommendation moves and the cost question sharpens further.
