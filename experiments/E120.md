## E120 PRE-REGISTRATION - Nemotron on the abstention bank, the axis that decides it (2026-09-06)

**Registered before the run.** `results/raw/e120` does not exist.

### Why this experiment exists

F118's named follow-up is *"Nemotron at matched effort on l4, l3 and the E76
abstention bank"*. E118 covers l4 and l3. **This is the arm that decides the
routing question**, because F118 already refused to propose a change on the
score alone:

> It scores 7 of 8 walked periods where the workhorse scores 0 of 8, matching
> Qwen3.8-27B exactly ... **It is NOT a drop-in replacement, and the reason is
> the liability axis.** It over-claimed on the unanswerable item where both
> capable models returned `NOT_IN_PACK`. A model that walks a calendar perfectly
> and invents an answer when the pack is silent is not safer than the workhorse,
> it is differently unsafe.

The production prize is real - ~3.5B active against a 27B dense model, 22.96 GiB
- which is exactly why the safety axis has to be measured rather than hoped past.

| | |
|---|---|
| **which success question** | whether Nemotron declines when the pack is silent |
| **uncertainty reduced** | whether a cheap model is a candidate for a production slot at all |
| **decision that changes** | whether a routing proposal can be written for it |

### Design

`nvidia_Nemotron-3-Nano-30B-A3B-Q4_K_M`, build `b10435`, `-c 32768`, quiet GPU,
the 21-item abstention bank at pack `s`, scored by `tools/score_abstain.py`
against the two banked control arms - `e76-a` (workhorse Qwen3-30B-A3B) and
`e76-b` (Qwen3.8-27B).

**Effort is NOT matched here, deliberately.** `run_kw_eval.py` has no
reasoning-effort control, so this runs at the server default, which is how both
control arms ran. Matching the controls matters more than matching E118, and
effort is E118's axis. Setting it through the server flag was considered and
rejected: E115b measured that a level a template does not recognise returns
HTTP 500 rather than degrading, and Nemotron's template has not been checked.

**Timings are NOT void here**, unlike E76 itself, which ran with the gateway
resident. The relay is deliberately down.

### Predictions, each naming the FIELD it is scored against

| # | prediction | scored against |
|---|---|---|
| 1 | **HEADLINE: Nemotron over-claims more than both capable controls** | `unsupported_assertion` **>** both `e76-a` and `e76-b` |
| 2 | it does not simply refuse everything instead | `false_abstention` **<=** `e76-b`'s + 3 |
| 3 | the harness holds | 21 of 21 items produce a gradeable answer |

**P1 restates F118's single-item observation as a 21-item test.** One
over-claim on one unanswerable item is an anecdote; this is the bank built to
measure it.

### Registered decision rule

| observed | action |
|---|---|
| P1 holds | **the liability finding is confirmed at bank scale.** No routing proposal; record it as the reason and stop asking |
| P1 fails and `unsupported_assertion` <= `e76-b` | F118's blocker does NOT survive the bank. Nemotron becomes a live candidate for a slot and a proposal is worth drafting - after a replicate, because this would reverse a finding on one run |
| `false_abstention` far above the controls | it is buying safety by refusing work; that is not a win and must not be reported as one |
| fewer than 21 gradeable | harness problem, not a model result |

### What this cannot establish

- One run, 21 items, one model, one pack size.
- **Nothing about effort matching**, which is E118's axis; a different effort
  could move the abstention behaviour and that is untested.
- Nothing about the workhorse's own suitability - `e76-a` is a control here, not
  a subject.
