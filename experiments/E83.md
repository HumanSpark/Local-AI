### The instrument is NOT the one the other corrected cells used - stated, not discovered later

The corrected Qwen3-Coder, Qwen3.8 and Mistral re-runs used guard **v2**
(`4dfe7ec`). This run uses **v3** (`021833c`). Per the closeout's own note,
`completed_correct` is graded independently of the guard - tests are restored
before grading - so **that field bridges all three guard versions**. The
guard-derived columns do not: `critical_error`, `commands_refused` and the
refusal list are not comparable to any earlier cell, and no comparison of them
is made here.

One v3 property noted in advance rather than found afterwards: v3 permits
`apply_patch` heredocs that add a file under `tests/`, because it judges by
redirect target and does not parse heredoc bodies. Grading integrity does not
rest on the screen - the runner restores every `tests/` file to its pre-run
state before grading - so this changes what is *screened*, never what is
*scored*.

### Decision rule, fixed in advance

- **C06 completes** - the corrected local total becomes **2 of 20**, gpt-oss is
  1/5, and the guard-defect account extends to the largest local model. The
  two-cell unknown closes.
- **Both fail with 0 refusals** - the cells close as genuine capability zeros.
  Local total is **1 of 20 with no unknowns**, and the coding branch shuts
  cleanly rather than on an asterisk.
- **Either cell records an `infrastructure_failure`, or the box wedges** - that
  cell stays UNVERIFIED and is reported as such. A runner-owned outcome is never
  folded into a capability count.
- **Tie-break, registered because it has already bitten once:** if C06 is
  `completed_correct` but `within_budget` is `False` - which is exactly what
  Qwen3.8 did at 942.95s against a 300s budget - it **counts as a completion**.
  `completed_correct` is the field named; budget is reported beside it, never
  netted against it.

### If it wedges

`bench` cannot power cycle. Per `docs/memory-edge-deadlock.md` the
evidence to capture before requesting the cycle, because `dmesg` does not
survive it: `/proc/<pid>/wchan` (`drm_suballoc_new` is the tell), `State` and
`VmRSS` from `/proc/<pid>/status`, `read_bytes` from `/proc/<pid>/io`, and the
amdgpu `mem_info_vram_used` figure (a park at exactly 2.00 GiB is the
fingerprint). This registration is committed and pushed **before** the load so
the forge tells the whole story if the box stops answering.
