## E72 PRE-REGISTRATION - tighten the S-H2 bound, and make `ok` mean ANSWERED (2026-08-19)

**Registered BEFORE the run.** This is not a repeat of E71. Two design defects
E71 exposed are corrected, and the sample is sized to move the bound rather than
to re-observe the same behaviour.

### Why this experiment exists

| | |
|---|---|
| **which success question** | *What percentage of my Claude Sonnet coding workload can I hand to the local machine without supervising it?* - E71 left the fault rate bounded only at 11.3%, which is too loose to clear an unattended arm |
| **uncertainty reduced** | the 95% upper bound on the load/decode fault rate moves from **11.3%** (n=25) to **3.0%** (n=100), if the run stays clean |
| **decision that changes** | at a bound near 3% with a completing answer on every cycle, gpt-oss-120b becomes admissible as a C-H2 batch arm behind a first-token watchdog. At 11.3% it is not |

### The three changes from E71, and why each is a correction rather than a retry

1. **`max_tokens` 32 -> 512.** E71's `ok` meant the decode ran, not that an
   answer arrived, because 32 tokens is inside gpt-oss's reasoning phase. At 512
   the probe answers `"ready"` and `ok` means what it says.
2. **`--cold` on every iteration.** Not because warm/cold was shown to matter -
   it was shown NOT to - but because demonstrating it 100 times costs nothing
   and removes the objection by measurement instead of by argument.
3. **n = 25 -> 100.** The only change that moves the bound. Estimated wall:
   100 x (22s load + 2s smoke + 5s settle) ~ **48 minutes**.

Everything else is held: same build, same shards, same `-c 8192 -np 1`, same
temperature, same abort rule, same six outcome classes.

### Predictions, each naming the FIELD it is scored against

| # | prediction | scored against |
|---|---|---|
| 1 | the run completes 100 iterations with `iterations_failed` = 0 | `iterations_failed` |
| 2 | no iteration matches the deadlock fingerprint | `possible_deadlock`, expected 0 |
| 3 | every `ok` iteration emits a non-empty content string | `smoke.text`, expected non-empty on all `ok` |
| 4 | cold loads are indistinguishable from E71's warm loads | `load_s_median`, within 5% of 22.02s |

**Prediction 1 reverses E71's prediction 1, and that is deliberate.** E71
predicted a failure and got none; predicting one again would be registering the
same guess twice and ignoring the evidence just collected. The falsifier is
symmetrical: any failure at all falsifies it, and would be worth far more than
the tightened bound.

**Prediction 4 is a control.** If cold loads at n=100 diverge from E71's warm
loads, the two-iteration probe that cancelled the larger cold soak was wrong,
and that is a finding about this lab's method rather than about the model.

### Decision rule, registered

| observed | verdict |
|---|---|
| any `possible_deadlock` | disqualified outright; soak stops; memory-edge doc governs |
| 0 failures in 100 | upper bound **3.0%**. Admissible as a C-H2 batch arm **behind a first-token watchdog**, whose deadline is set from the measured `ttft_s` distribution |
| 1-3 failures, all killable and all `stalled_before_first_token` | the watchdog is mandatory and its deadline comes from the failures; still no unsupervised clearance without one |
| any failure of a new shape | the shape is the finding; no clearance |

**Still not a clearance for the model.** The best available outcome remains
"rare, killable, and caught by a watchdog", which clears a SYSTEM containing a
watchdog. F86's model-versus-system separation applies to reliability exactly as
it does to capability.

## E72 RESULT - 100/100 cold, all four predictions HELD, and S-H2 CLOSES (2026-08-19)

100 independent cycles, every one with all three shards evicted from the page
cache first (`posix_fadvise(DONTNEED)`, verified `ok` on all 300 shard
evictions). `max_tokens` 512, `-c 8192 -np 1`, `llama.cpp/wt/b10435`, kernel
7.0.0-28.

| field | measured |
|---|---|
| `iterations_ok` | **100 / 100** |
| `iterations_failed` | **0** |
| `possible_deadlock` | **0** |
| `load_s` median (min / max) | **22.02s** (22.01 / 26.03) |
| `load_s_first5` -> `last5` median | 24.02 -> 22.02, drift **-8.3%** |
| `ttft_s` median (min / max) | **0.87s** (0.85 / 0.94) |
| smoke total (min / max) | 1.92s / 2.04s |
| content string | **`"ready"` on all 100** |
| teardown | `sigterm` on all 100 |
| GTT peak | 63.06 GiB, identical on every iteration |

### Scoring

| # | prediction | outcome |
|---|---|---|
| 1 | `iterations_failed` = 0 over 100 | **HELD** |
| 2 | `possible_deadlock` = 0 | **HELD** |
| 3 | every `ok` iteration emits non-empty content | **HELD** - 100/100, all `"ready"` |
| 4 | cold `load_s_median` within 5% of E71's warm 22.02s | **HELD - 0.0%** |

### I DOUBTED PREDICTION 4 TWICE, ON SMALLER SAMPLES, AND WAS WRONG BOTH TIMES

Mid-run I read the running median at n=4 (24.02s) and n=12 (23.03s) and recorded
that cold loads looked 9-14% slower and that prediction 4 was heading for
falsification. **At n=100 the median is 22.02s - identical to warm, to two
decimal places.**

What actually differs is the SHAPE, not the centre: the first five iterations
median 24.02s and the maximum reaches 26.03s, against E71's tight 22.01-24.02
warm range. Cold loads have a slower opening and a longer tail around the same
median.

The lesson is the one this lab keeps relearning from the other direction. The
original two-iteration probe concluded cold ~ warm and was RIGHT; the doubt that
followed came from reading a median on four samples, which is a smaller sample
than the one it was doubting. **Suspect the ruler before the data - including
when the ruler is your own running average.**

### S-H2 IS CLOSED

| | E71 | E72 |
|---|---|---|
| iterations | 25 (warm) | **100 (cold)** |
| failures | 0 | **0** |
| 95% upper bound on the fault rate | 11.29% | **2.95%** |

Combined, **125 controlled load-and-decode cycles with zero failures**, spanning
both page-cache states, on the exact configuration and build that produced the
2026-08-19 fault.

**Verdict under the rule registered before the run:** gpt-oss-120b is
**admissible as a C-H2 batch arm behind a first-token watchdog**. The measured
TTFT distribution sets that watchdog's deadline and sets it very comfortably -
median 0.87s, maximum 0.94s across 100 cold loads, so a first-token deadline of
even 30 seconds is thirty times the worst observed value and would fire only on
the stalled-decode shape the fault actually takes.

**What is still NOT established, and the distinction is the whole of F86.** This
clears a SYSTEM containing a watchdog, not the model. The 2026-08-19 fault
remains **undiagnosed** - 125 clean cycles is a rate, not a mechanism, and
`docs/2026-08-19-gptoss120b-decode-hang.md` stays open. A model that fails once
in a way nobody understands is not the same as a model that does not fail.
