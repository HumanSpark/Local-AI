### The item-level check is the one that counts

[[F117]]: *a control that reproduces its own ITEMS, not just its score, is what
licenses a cross-build comparison.* Both do.

Two variables moved between the control and this run - the runtime went
`067de9371` -> `daef7b687`, and the path went from a raw bench server to the
production gateway. **Identical failures at item level across both makes a
hidden compensating change implausible**, which is more than the matching totals
alone would support.

### Deliberately run through the gateway, and what that costs

CLAUDE.md says sparkbench benches raw `llama-server` and never the relay,
because proxy overhead muddies the numbers. **That rule protects CAPABILITY
figures.** The question here is whether the production path still works after a
two-month runtime jump, so the production path is the correct thing to exercise.

Consequently these are a **regression signal, not new bench figures**, and the
wall times are not comparable to anything - `e33`'s 58 s and 60 s were measured
on a different path and are not a baseline for the 49 s and 53 s here.
