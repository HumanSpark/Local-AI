## E62: does gpt-oss-120b's 12/12 REPRODUCE? (2026-08-19, pre-registered before the run)

**Why this and nothing else first.** E61 recorded gpt-oss-120b at **12/12** on
L3-hard in 178.7s. That is ONE run, and the *identical* configuration - same
binary (`llama.cpp/wt/b10435`), same shards, same flags - failed entirely
immediately before it: twelve `transport_failed` from a decode hang that is
still unexplained (`docs/2026-08-19-gptoss120b-decode-hang.md`). A single run
from a configuration with a demonstrated intermittent fault is not a
load-bearing capability result, and every downstream question in the R&D
programme (robustness, efficiency, system value) is priced off it.

**Design.** Exact repeat, nothing varied: `--tier l3 --distractors 0
--max-tokens 4096 --ctx 32768 --thinking default`, same `--server-bin`. The only
difference is a fresh server process and a fresh label.

### Predictions

1. **PRIMARY: 12/12 again, all twelve questions completing (`finish_reason:
   stop`, zero `transport_failed`).** E61's run was clean throughout - no
   truncation, no transport error - and the hang struck at first decode, not
   mid-run.
2. **Every answer byte-identical to E61's.** Temperature is fixed and E57
   already showed this model class reproducing byte-for-byte across separate
   processes.
3. **Wall time within +/-15% of 178.7s** (152 - 206s).
4. **The decode hang does NOT recur.** It has been observed once in three loads
   of this model today.

**Falsifiers, and what each would mean:**

- **Any score below 12/12 on a completed run** - E61's 12/12 was not a stable
  property of the model and the headline must be re-stated as a range, not a
  figure. This is the result that would most change the programme.
- **A recurrence of the decode hang** - the intermittency is frequent enough to
  disqualify gpt-oss-120b from any unattended role regardless of its score, and
  diagnosis stops being optional. Record it as an instrument failure, NOT as a
  capability score (the E61 rule stands).
- **Answers differing while the score holds** - determinism is not a property of
  this arm, so per-question cells are not reproducible and only the aggregate is
  citable (the F76 treatment).

**Cost.** One arm, ~3 minutes of run plus a 59.03 GiB load. Near-edge for the
amdgpu suballocator deadlock: box quiet, no concurrent download, backup or
hashing, run attended.

### E62 RESULT: it reproduces, and it is BIT-DETERMINISTIC (2026-08-19 07:58)

**12/12 again, and all four predictions held.** Not merely the same score - the
same computation.

| | E61 retry | E62 repeat |
|---|---|---|
| score | 12/12 | **12/12** |
| citations valid | 12/12 | 12/12 |
| over-claims | 0/1 | 0/1 |
| wall | 178.7s | **178.0s** (-0.4%) |
| median question | 13.28s | 13.22s |
| `finish_reason` | all `stop` | all `stop` |
| `transport_failed` | 0 | **0** |

**Every one of the twelve answers is byte-identical**, and so is every
`completion_tokens` count and every `reasoning_chars` count, to the character -
`M2` emits 1,311 tokens and 4,361 reasoning characters in both runs. The two
serverlogs are the same size to the byte (6,809,768). This is a separate process,
a separate server, a separate load of 59.03 GiB.

**What that does and does not settle.** It settles that E61's 12/12 was not a
sampling fluke: the arm is deterministic, so the score is a property of the
model-plus-config rather than of one lucky draw. It does **not** settle
robustness - a deterministic arm reproduces its errors as faithfully as its
successes, and E57's design exists precisely because a strong single-turn result
can vanish when the context structure changes. Prerequisite 1 is closed;
prerequisite 2 is not.

**The hang did not recur, and here is the honest denominator.** Counting every
load of this model on 2026-08-19: the failed L3 run, the smoke test, the
bisect ladder, the E61 retry, and E62 - **one hang in five loads**. n=5 is far
too small for a rate; what it supports is that the fault is real, intermittent,
and has now been survived four consecutive times. It remains unexplained and it
remains disqualifying for an unattended role until it is either diagnosed or
observed not to recur over a much larger number of loads.
