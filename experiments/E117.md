## E117 PRE-REGISTRATION - does the SERVER path score what the REQUEST path scored? (2026-09-06)

**Registered before the run.** `results/raw/e117` does not exist.

### Why this experiment exists

E115 measured the server flag and the per-request parameter producing
**different generations at the same nominal level** - A1 (`--reasoning-effort
medium`, nothing requested) against B2 (no flag, `reasoning_effort: medium`)
differ by 1248/746 vs 1131/691 on one prompt and by wording on the other. E115c
then measured cross-restart identity holding byte-for-byte on both prompts, so
that difference is the two paths and not process variation.

**This matters because of which path our evidence used.** Every quality figure
behind the serving proposal - E42's `medium` 7/8, E101's 6-of-6 and 18-of-18,
E104's 7/8 - was measured by sending `reasoning_effort` in the request body.
**sparkrouter would deploy the other path**: the flag on the unit, with callers
silent. That is Rule 8's concern exactly - a benchmark measures a CONFIG, and the
config we measured is not the config that would ship.

| | |
|---|---|
| **which success question** | whether the deployable path scores what the measured path scored |
| **uncertainty reduced** | whether the proposal's evidence transfers to the proposal's mechanism |
| **decision that changes** | whether the proposal can cite E42/E101/E104 at all |

### Design

One arm. `Qwen3.8-27B-Q4_K_M`, `--task-set expert`, `-c 32768 --max-tokens
24576`, build `b10435`, `--exec-timeout 15`, quiet GPU - **identical to E104's
incumbent arm in every respect but one**: effort is set by
`--server-extra '--reasoning-effort medium'` and the request sends nothing
(`--thinking default`), where E104 sent `reasoning_effort: medium` per request
with no server flag.

**Control:** E104's banked `e104-incumbent-q4km`, **7/8, 6,206.5 s**, same bank,
same build, same box.

`run_coding_eval.py` gained `--server-extra` for this; the flag is recorded in
the output so the two arms are distinguishable in the record forever.

- One run, one bank, one model. The expert tier separates models well (7/8, 4/8,

- Nothing about short-turn behaviour, which is E116's question.
- Nothing about `low` or `xhigh` on the server path.

## E117 RESULT - the two paths score identically, to the token (2026-09-06)

`--task-set expert`, effort set by `--server-extra '--reasoning-effort medium'`
with the request sending nothing. Control: E104's `e104-incumbent-q4km`, same
bank, same build, same box, effort sent per request.

| | E104, request path | E117, server path |
|---|---|---|
| score | 7/8 | **7/8** |
| failing task | `sliding_median` | **`sliding_median`** |
| total tokens | 74,796 | **74,796** |
| wall | 6,206.5 s | 6,201.0 s |

| # | prediction | outcome |
|---|---|---|
| 1 | HEADLINE: `passed` = 7 of 8 | **held** |
| 2 | the failing task is `sliding_median` | **held** |
| 3 | total tokens differ from E104 by >= 5% | **FALSIFIED** - identical |
| 4 | `no_code` and `transport_failed` both 0 | held |

### THE ANSWER

> **The proposal's evidence transfers to the proposal's mechanism.** Every
> quality figure behind it - E42, E101, E104 - was measured by sending
> `reasoning_effort` in the request body, and sparkrouter would set the flag on
> the unit instead. Those are the same computation on this bank: same score,
> same failing task, same 74,796 tokens, 5.5 s apart over 1h43m.

### This contradicts E115, and E115 is the one that is probably wrong

E115 concluded the two paths produce different generations at the same nominal
level, from A1 (1248/746) differing from B2 (1131/691). E117 is eight tasks and
74,796 tokens of the opposite, which is far heavier evidence than four short
generations.

**The likely confound is REQUEST POSITION, which E115 did not control.** Each
arm ran its two cells inside ONE server process, in order: arm A produced
A1-counting, A1-scheduling, A2-counting, A2-scheduling; arm B produced
B1-counting, B1-scheduling, B2-counting, B2-scheduling. So A1 was the 1st and
2nd request of its process and B2 was the 3rd and 4th of its own. E115
Amendment 2 replicated A1 across RESTARTS and found byte-identity, but never
varied position WITHIN a process - so a per-process effect such as cache or slot
state would have passed that check untouched.

**E115's cross-path claim is therefore withdrawn pending a position test**, and
the test is registered rather than left as a remark: run the same cell as the
1st and as the 4th request of one process; if they differ, position is the
explanation and E115's conclusion was an artefact of run order.

A1 == B2 in outcome is also the reading E117 supports and E115's own P2 already
recorded: A1 was within 1.00x and 1.10x of B2, which is agreement, not
difference. I read the 1.10x as a difference because I was looking for one.
