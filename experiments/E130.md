## E130 - tool calling after the runtime upgrade and the effort flag (2026-09-07)

Smoke test against the live gateway after both changes, all three residents, one
function schema, `tool_choice: auto` per F99 - `any` forces a call and hides
whether the model would choose it.

| model | should fire | should NOT fire | call latency |
|---|---|---|---|
| `local_smart` | called, valid JSON, `finish=tool_calls` | no call, answered in text | 9.4 s |
| `local_fast` | called, valid JSON | no call, answered in text | 1.0 s |
| `local_code` | called, valid JSON | no call, answered in text | 1.0 s |

**6 of 6.** Every call named the right function and produced parseable arguments,
including inferring the optional `currency: EUR` from "in euro" when only
`invoice_number` was required. All three declined correctly on the negative
branch, which the routing guide names as the weak spot: *"all three models are
reliable when the flag SHOULD fire and unreliable when the correct action is to
do nothing"*.

### What this does and does not establish

**Establishes:** tool calling is not obviously broken by the two-month runtime
jump or by the `medium` default. That was the largest unmeasured risk in the
upgrade and it is now bounded.

**Does NOT establish that the rates held.** The banked baseline is 13 paired
conditional tasks - Qwen3.8-27B at `medium` 86%, workhorse 68%, and noisy at
about +/-1 run per cell (F76). One tool and one prompt pair cannot speak to that,
and a 6-of-6 smoke test is not a 13-task suite. Anyone relying on a conditional
flow should still test their own condition on the branch where it must NOT fire.

### A cost worth watching

`local_smart` took **9.4 s** to a tool call against `local_fast`'s **1.0 s**. The
new default makes it reason before calling. **There is no pre-flag measurement of
this path**, so whether the flag made it slower is unmeasured - though on the
E129 prompt `medium` emitted more tokens than the old `xhigh` default, so it
plausibly did. If tool-call latency on the smart model matters to a caller, that
caller can send `reasoning_effort: xhigh` per request, which E129 confirmed still
overrides.

The banked 86% figure was itself measured AT `medium`, so the production default
now matches the configuration that scored best on conditional tool use.
