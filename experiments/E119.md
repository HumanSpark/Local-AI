## E119 PRE-REGISTRATION - does REQUEST POSITION change the output? (2026-09-06)

**Registered before the run.** `results/raw/e119` does not exist.

### Why this experiment exists

E115 claimed the server flag and the per-request parameter produce different
generations at the same nominal level. E117 measured the two paths scoring
identically over eight tasks and 74,796 tokens, so that claim was withdrawn -
but withdrawn is not explained, and an unexplained contradiction between two of
my own runs is exactly what must not cross a context boundary.

**The confound E115 could not see is request POSITION.** Each arm ran two cells
inside one server process, in order, so A1 was the 1st and 2nd request of its
process while B2 was the 3rd and 4th of its own. E115 Amendment 2 replicated A1
across RESTARTS - same position, fresh process - so any per-process effect that
accumulates would have passed that check untouched.

| | |
|---|---|
| **which success question** | whether E115's difference was the paths or the run order |
| **uncertainty reduced** | why two of my runs disagree |
| **decision that changes** | whether E115's withdrawn claim is retracted outright or reinstated |

### Design

Two cells, `Qwen3.8-27B-Q4_K_M`, build `b10435`, greedy, `--max-tokens 3072`.

- **P - the mechanism.** One process, the IDENTICAL request (`reasoning_effort:
  medium`, the `scheduling` prompt) four times in a row.
- **Q - the direct replication.** One process, E115 arm B's exact sequence and
  order: B1-counting, B1-scheduling, B2-counting, B2-scheduling.

### Predictions, each naming the FIELD it is scored against

| # | prediction | scored against |
|---|---|---|
| 1 | **HEADLINE: position changes nothing** | `P_all_positions_identical` is **true** |
| 2 | and the replication agrees with E115's own arm B | `Q_B2_scheduling` = **[1131, 691]** |
| 3 | nothing is clipped | `finish_reason` `stop` in all 8 |

**P1 and P2 are in deliberate tension, and that is the point.** If position does
nothing AND B2 reproduces 1131 while A1 reproduces 1248, then the two paths
really do differ on short prompts and E117's agreement is the thing needing
explanation - not the reverse. Registering both stops me choosing afterwards
which result to believe.

### Registered decision rule

| observed | action |
|---|---|
| P identical, Q = [1131, 691] | position is NOT the cause. E115's difference is real on short prompts and does not reach an 8-task score; both results stand and the write-up says so |
| P differs by position | **position is the cause.** E115's cross-path claim is RETRACTED outright, not merely withdrawn |
| P identical, Q = [1248, 746] | E115's B2 measurement did not reproduce. Retract the claim and record it as a one-off that survived a determinism check it should not have |
| any other Q value | neither prior value reproduces; the short-prompt cells are unstable and nothing may be concluded from any of them |

### What this cannot establish

- One model, one build, one prompt pair. It explains a disagreement between two
  of my runs; it is not a general claim about llama.cpp.
- Nothing about the production relay, which batches and would not be expected to
  reproduce anything byte-for-byte.

## E119 RESULT - position is not the cause, but request HISTORY is, and my decision rule missed it (2026-09-07)

| cell | sequence | result |
|---|---|---|
| P pos1-4 | the SAME request (`medium`, `scheduling`) four times in one process | **1012 / 640, all four identical** |
| Q pos1 | `B1` counting | 337 / 220 |
| Q pos2 | `B1` scheduling | 775 / 404 |
| Q pos3 | `B2` counting | 633 / 515 |
| Q pos4 | `B2` scheduling | **1131 / 691** |

| # | prediction | outcome |
|---|---|---|
| 1 | HEADLINE: `P_all_positions_identical` is true | **held** |
| 2 | `Q_B2_scheduling` = [1131, 691] | **held, exactly** |
| 3 | all 8 `stop` | held |

### The registered rule fires, and it is wrong to apply it as written

The rule said: *P identical and Q reproducing means position is NOT the cause,
E115's difference is real, both results stand.* **P produced a third value the
rule did not anticipate, and it changes the reading.**

`B2`-scheduling is **1131** in E115 and **1131** in Q - reproducing exactly. The
IDENTICAL request in cell P, run alone in a fresh process, is **1012**. Same
model, same flag state, same prompt, same effort, same build.

So:

- **Repeating one request does not drift** - four in a row are byte-identical.
- **But a request preceded by DIFFERENT requests returns a different result.**
  1012 alone, 1131 after three other prompts.

**Position is not the variable. Request HISTORY is.** The economical explanation
is slot KV-cache reuse: a repeated prompt hits its own cache fully, while a
different preceding prompt leaves a partial prefix that changes the numerics
slightly. Not proven here - only the effect is measured.

### What this does to the E115 / E117 disagreement: still unresolved, and now for a better reason

E115 compared `A1`-scheduling (preceded by one request) against `B2`-scheduling
(preceded by three). **Those cells had different histories, and history is now a
measured variable.** The comparison was confounded - not by run order as I
guessed, but by what ran before.

So the cross-path claim is **still not settled**, and E117's eight-task agreement
remains the heavier evidence that the paths do not differ where it counts. What
would settle it is a comparison with IDENTICAL predecessor sequences on both
sides, which no run so far provides.

**My decision rule was under-specified.** It offered four outcomes and the data
landed outside all of them: both its conditions were met while its conclusion
became unsupportable. Registering a rule does not make it exhaustive, and
applying this one mechanically would have reinstated a claim the evidence does
not support.

### Practical consequence, beyond this repo's argument

**A single request's output on this server can depend on what was served before
it in the same process.** Cross-restart determinism holds (E115c). Determinism
*within* a process, across a varied workload, does not. Any future arm that
compares two configurations must serve them the same predecessor sequence, or
control the effect by restarting between cells.
